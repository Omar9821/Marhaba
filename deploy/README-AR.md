# تشغيل مرحبا / GLASSTA على سيرفر خاص يخدم كل الفروع

يشغّل هذا المجلد كل شيء على جهاز واحد: قاعدة البيانات (MongoDB) + الخادم (API) + واجهة الويب مع HTTPS. تبقى كل البيانات (القاعدة المركزية وقاعدة كل فرع) على جهازك، ولا تُنشر قاعدة البيانات خارج السيرفر.

> **الحالة:** الحزمة مكتوبة وفُحص تركيبها (صياغة ملف التشغيل والسكربتات) لكنها **لم تُجرَّب على سيرفر Docker حقيقي بعد**. جرّبها أولًا بالتوازي مع السحابة دون قطع العمل الحالي.

## 1. المتطلبات
- جهاز Linux (Ubuntu 22.04 أو أحدث) بذاكرة **4 غيغابايت على الأقل** (البناء الأول يستهلك ذاكرة)، وقرص SSD، ومصدر طاقة احتياطي (UPS).
- Docker وDocker Compose: https://docs.docker.com/engine/install/ubuntu/
- اتصال إنترنت مستقر لكل الفروع، وطريقة وصول من الخارج (القسم 3).

## 2. التثبيت
```bash
git clone https://github.com/Omar9821/Marhaba.git
cd Marhaba/deploy
cp .env.example .env      # ثم عدّل القيم بمحرر نصوص
docker compose --env-file .env up -d --build
```
بعد دقائق افتح العنوان `PUBLIC_URL` وادخل بحساب `OWNER_EMAIL` لإضافة الفروع. للمتابعة: `docker compose logs -f api`.

## 3. كيف تصل الفروع إلى السيرفر
| الطريقة | متى تناسب |
|---|---|
| **Cloudflare Tunnel (أو Tailscale)** | الأسهل والأأمن إن لم يكن لديك عنوان IP ثابت؛ لا تفتح منافذ في الراوتر. |
| **توجيه المنفذين 80 و443 + عنوان IP ثابت + نطاق** | إن وفّر مزوّد الإنترنت عنوانًا ثابتًا. اجعل `SITE_ADDRESS` اسم النطاق فتُصدر Caddy شهادة HTTPS تلقائيًا. |
| **شبكة داخلية فقط** | إن كان العمل كله في موقع واحد: `SITE_ADDRESS=:80` و`PUBLIC_URL=http://عنوان-السيرفر`. (الإشعارات وتثبيت التطبيق على الهاتف يتطلبان HTTPS.) |

## 4. نقل البيانات من السحابة الحالية
1. من لوحة Render انسخ قيمة `ENCRYPTION_KEY` و`JWT_SECRET` (و`VAPID_*`) إلى `.env` الجديد. **يجب أن يكون `ENCRYPTION_KEY` هو نفسه تمامًا**، وإلا لا تُقرأ الهواتف والرواتب المشفّرة.
2. على جهاز فيه `mongodb-database-tools` نفّذ: `./migrate-from-atlas.sh "رابط اتصال Atlas"`.
3. انقل الملف إلى السيرفر ونفّذ: `./restore.sh backups/atlas-XXXX.archive.gz`.
4. تحقق من الدخول وبيانات الفروع قبل تحويل العمال إلى العنوان الجديد، وأبقِ السحابة شغّالة أسبوعًا احتياطًا.

## 5. النسخ الاحتياطي (إلزامي)
- يدويًا: `./backup.sh`. جدولة يومية: `crontab -e` ثم `0 2 * * * /مسار/Marhaba/deploy/backup.sh >> /مسار/Marhaba/deploy/backups/backup.log 2>&1`
- تُحفظ 30 يومًا في `deploy/backups`. **لا يكفي القرص نفسه**: انسخ المجلد دوريًا إلى قرص خارجي أو سحابة (مع `rclone` عرّف `REMOTE`).
- **جرّب الاستعادة مرة** على جهاز اختبار قبل الاعتماد على النسخ.

## 6. التحديث
```bash
cd Marhaba && git pull && cd deploy && docker compose --env-file .env up -d --build
```

## 7. الأمان
- لا تفتح إلا المنفذين 80 و443 (وSSH بمفتاح لا بكلمة مرور). قاعدة البيانات داخلية ولا تُنشر.
- كلمات مرور قوية لكل قيمة في `.env`، ولا تُشارك الملف. غيّر كلمات المرور الافتراضية بعد أول دخول.
- فعّل التحديثات الأمنية التلقائية لنظام التشغيل (`unattended-upgrades`).
- راجع مع محامٍ التزامات حماية المعطيات الشخصية (القانون 18-07) لأن الاستضافة صارت مسؤوليتك.

## 8. ملاحظات
- **الإشعارات:** يعمل الاشتراك مرتبطًا بالعنوان، فيُعيد العمال تفعيل الإشعارات بعد الانتقال إلى النطاق الجديد.
- **ملف APK:** عنوان الخادم يُضمَّن وقت البناء، فيلزم بناء APK جديد بالعنوان الجديد.
- **انقطاع الكهرباء أو الإنترنت:** يتوقف التطبيق لكل الفروع حتى يعود السيرفر؛ لهذا يلزم UPS ومراقبة دورية (`docker compose ps`).
